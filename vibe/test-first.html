06. 테스트를 먼저 요구하기

기능 수정 전에 실패하는 검증 스크립트를 먼저 작성하게 하고 통과 여부로 완료를 판단할 수 있다.

개념 읽기 → 실습 → 확인 문제 5개 모두 맞히기 → 튜터와 대화로 다지기

왜 여기서 막히나

AI가 「수정했습니다」라고 답변하면 대부분 눈대중으로 대충 훑어보고 성공했다고 믿어버립니다. 그러나 실제로 실행해 보면 특정 조건에서 멈추거나 엣지 케이스가 전혀 처리되지 않은 경우가 빈번합니다. 검증 코드가 없으면 코드가 늘어날 때마다 과거에 잘 되던 기능이 여전히 살아있는지 사람이 일일이 수동 테스트해야 합니다. 통과해야 할 객관적인 채점 기준표를 먼저 만들게 해야 AI의 완료 선언을 검증할 수 있습니다.

핵심 개념 세 가지

  1. 실패하는 테스트 우선 작성기능을 고치기 전에 현재 상태에서는 무조건 실패하는 검사 스크립트를 먼저 만드는 기법입니다. 문제가 실제로 존재함을 기계적으로 확인한 뒤 수정을 시작합니다. 코드가 고쳐진 후 해당 검사가 성공으로 바뀌어야만 비로소 작업 완료로 인정합니다.
  2. 검증 스크립트 기반 완료 판정AI의 말 한마디를 믿지 않고 독립된 검증 스크립트의 종료 코드나 출력 결과로 작업 완료를 판정하는 방식입니다. 자동화 스크립트에서는 입력 대비 출력값 검사가 테스트가 됩니다. 검증 명령어가 오류 없이 종료될 때만 다음 단계로 넘어갑니다.
  3. 브라우저 관찰 검증화면 인터페이스 개발에서는 콘솔 에러 유무 확인과 스크린샷 검토가 테스트 역할을 대신합니다. AI에게 요소를 렌더링한 뒤 콘솔 로그에 경고나 에러가 없는지 스크립트로 확인하게 만듭니다. 주관적인 육안 검사를 객관적인 관찰 지표로 변환합니다.

같은 일, 다른 요청

이렇게 요청하면

엑셀 날짜 형식이 깨지는데 그거 고쳐 줘. 다 되면 다 됐다고 말해 줘.

이렇게 요청한다

엑셀 파일에서 2024. 1. 5 형식의 텍스트 날짜를 읽었을 때 YYYY-MM-DD 표준 문자열로 변환하는 함수를 수정해야 합니다.

본격적인 수정에 앞서, 아래 세 가지 입력값에 대해 현재 함수가 실패하는지 확인하는 검증 스크립트 test_date.py를 먼저 작성해 주십시오.
- 입력 1: '2024. 1. 5' -> 기대 출력: '2024-01-05'
- 입력 2: '2024-02-29' -> 기대 출력: '2024-02-29'
- 입력 3: 빈 문자열 '' -> 기대 출력: None

이 테스트를 실행하여 실패함을 먼저 보여주십시오. 그 후 실제 코드를 수정하고, 해당 테스트가 모두 통과하는 터미널 결과를 제시하십시오.

단순히 고쳐달라고 맡기지 않고 구체적인 검증 케이스 세 가지를 명시했습니다. 수정 전 실패 확인과 수정 후 통과 검증 절차를 강제함으로써 AI가 임의로 완료를 주장하지 못하게 막았습니다.

30분 실습

  1. 현재 프로젝트에서 가장 자주 사용하는 함수 하나를 선택합니다.
  2. AI에게 해당 함수에 정상 값과 비정상 값을 넣었을 때의 결과를 비교하는 단독 테스트 스크립트를 작성하라고 요청합니다.
  3. 터미널에서 테스트 스크립트를 직접 실행하여 통과(PASS) 또는 실패(FAIL) 출력이 나오는지 확인합니다.
  4. 기능을 추가할 때 이 테스트 스크립트를 먼저 실행하고 통과한 뒤에만 git commit을 진행합니다.

통과 기준

  • 실제 코드 수정 전에 실패를 증명하는 스크립트를 먼저 확보했습니다.
  • 테스트 실행 결과가 성공으로 바뀌는 것을 터미널 로그로 직접 확인했습니다.
  • AI의 완료 선언 대신 스크립트의 정상 종료 상태를 보고 완료를 승인했습니다.

확인 문제

다섯 문제를 모두 맞혀야 이 단계를 통과합니다. 틀리면 해설을 읽고 다시 풀면 되고, 다시 풀 때마다 문제와 보기 순서가 바뀝니다.

튜터와 다지기

문제를 맞혔어도 내 프로젝트에서 바로 쓰지 못하면 아직 아는 것이 아닙니다. 아래 프롬프트를 Claude에 붙여 넣으면 「통과」라고 할 때까지 내 상황에 맞춘 질문을 계속 받습니다.

너는 내 바이브 코딩 튜터다. 나는 「테스트를 먼저 요구하기」 단계를 공부하고 있다.
이 단계의 목표는 「기능 수정 전에 실패하는 검증 스크립트를 먼저 작성하게 하고 통과 여부로 완료를 판단할 수 있다.」
다룰 개념은 「실패하는 테스트 우선 작성」, 「검증 스크립트 기반 완료 판정」, 「브라우저 관찰 검증」이다.

규칙
1. 설명부터 하지 말고, 내가 지금 만드는 프로젝트가 무엇인지 먼저 한 가지만 묻는다.
2. 질문은 한 번에 하나씩. 내 프로젝트 상황에 맞춘 문제를 낸다.
3. 내가 틀리면 정답을 바로 말하지 말고 힌트를 하나 준 뒤 다시 묻는다.
4. 개념마다 내가 실제로 보낼 프롬프트를 직접 써 보게 하고, 부족한 점을 고쳐 준다.
5. 서로 다른 상황 문제 세 개를 연속으로 맞히면 「통과」라고 말하고, 아직 약한 부분을 한 줄로 알려 준다.
6. 통과하기 전에는 다음 단계로 넘어가지 않는다.
