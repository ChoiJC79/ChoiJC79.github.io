12. AI 코드 검수와 안전 수칙

인공지능이 제안한 변경 사항을 안전하게 검수하고 위험한 명령어 실행을 차단할 수 있다.

개념 읽기 → 실습 → 확인 문제 5개 모두 맞히기 → 튜터와 대화로 다지기

왜 여기서 막히나

인공지능이 작성한 코드를 확인도 없이 무조건 수락하면 숨겨진 버그나 보안 취약점이 그대로 운영 환경에 배포됩니다. 특히 데이터베이스 삭제나 원격 저장소 강제 푸시 같은 명령은 한 번 실행되면 복구하기 어렵습니다. 겉보기에 잘 작동하는 것처럼 보여도 기존에 잘 돌아가던 핵심 기능 코드를 인공지능이 슬그머니 지워버리는 일이 자주 생깁니다. 변경 내역을 꼼꼼히 확인하고 교차 검증하는 절차를 습관으로 만들어야 안전하게 개발을 지속할 수 있습니다.

핵심 개념 세 가지

  1. 코드 변경 검수 순서(git diff)인공지능이 수정한 내용을 반영하기 전에 무엇이 바뀌었는지 단계별로 확인하는 절차입니다. 변경된 줄만 보는 것이 아니라 의도치 않게 삭제된 코드가 없는지, 비밀 키나 개인정보가 직접 노출되지 않았는지 확인합니다. 터미널에서 git diff 명령어를 실행하여 변경 내역을 대조합니다.
  2. 되돌릴 수 없는 위험 명령어 차단실행 즉시 되돌릴 수 없는 피해를 주는 치명적인 명령어를 선별하여 관리하는 원칙입니다. 폴더 강제 삭제(rm -rf), 원격 저장소 덮어쓰기(git push --force), 테이블 초기화 같은 작업이 여기에 해당합니다. 이러한 명령어는 인공지능이 자동으로 실행하지 못하게 막고 사람이 직접 확인한 뒤 승인해야 합니다.
  3. 다른 모델을 활용한 교차 검수코드를 작성한 인공지능에게 스스로 검토를 시키지 않고 다른 모델이나 새로운 세션에 검수를 맡기는 검증 기법입니다. 자신이 작성한 코드의 논리적 오류를 스스로 발견하기 어려운 인공지능의 한계를 보완합니다. 독립된 시각에서 보안 결함이나 예외 처리 누락을 찾아내어 코드 품질을 높입니다.

같은 일, 다른 요청

이렇게 요청하면

코드가 잘 안 돌아가는데 알아서 다 고쳐주고 바로 깃허브에 커밋하고 푸시까지 한 번에 끝내줘.

이렇게 요청한다

1. 오류가 발생한 원인을 먼저 분석하고 어떤 파일을 어떻게 수정할 것인지 계획 모드에서 설명합니다.
2. 실제 파일을 수정한 뒤에는 즉시 커밋하지 말고 git diff 결과를 출력하여 변경된 내용을 보여줍니다.
3. 기존 로직이 삭제된 부분이 없는지 확인하고 개인정보나 API 인증 키가 소스에 포함되었는지 점검합니다.
4. 로컬 테스트를 실행하여 정상 동작을 확인한 뒤 사용자 승인을 받고 커밋을 준비합니다.

bad는 검증 단계 없이 모든 변경과 원격 반영을 인공지능에게 위임하여 심각한 장애나 코드 유실을 부를 수 있습니다. good은 수정 계획 확인, 변경 내역 대조, 보안 점검, 로컬 테스트라는 검수 절차를 거치도록 강제합니다. 사용자가 모든 변경 사항을 통제할 수 있어 안전합니다.

30분 실습

  1. 1. 터미널에서 임의로 소스 코드 한 줄을 수정한 뒤 git diff 명령어를 실행하여 변경 내역이 어떻게 표시되는지 확인합니다.
  2. 2. Claude Code 대화창에서 Shift+Tab을 눌러 계획 모드로 전환한 뒤 코드 수정 계획을 먼저 설명하게 합니다.
  3. 3. 수정한 파일 안에 민감한 개인정보나 비밀 키가 포함되어 있는지 검색 도구로 검사합니다.
  4. 4. 새로운 대화창을 열어 작성된 코드의 보안 취약점과 삭제된 주요 기능을 비판적으로 검토하도록 교차 검수를 요청합니다.

통과 기준

  • 1. 코드 수정 후 바로 커밋하지 않고 git diff를 통해 변경된 줄과 삭제된 줄을 직접 확인했습니다.
  • 2. rm -rf나 git push --force 같은 파괴적 명령어의 위험성을 인지하고 자동 실행을 차단했습니다.
  • 3. 독립된 프롬프트나 다른 모델을 통해 작성된 코드의 잠재적 버그를 교차 점검했습니다.

확인 문제

다섯 문제를 모두 맞혀야 이 단계를 통과합니다. 틀리면 해설을 읽고 다시 풀면 되고, 다시 풀 때마다 문제와 보기 순서가 바뀝니다.

튜터와 다지기

문제를 맞혔어도 내 프로젝트에서 바로 쓰지 못하면 아직 아는 것이 아닙니다. 아래 프롬프트를 Claude에 붙여 넣으면 「통과」라고 할 때까지 내 상황에 맞춘 질문을 계속 받습니다.

너는 내 바이브 코딩 튜터다. 나는 「AI 코드 검수와 안전 수칙」 단계를 공부하고 있다.
이 단계의 목표는 「인공지능이 제안한 변경 사항을 안전하게 검수하고 위험한 명령어 실행을 차단할 수 있다.」
다룰 개념은 「코드 변경 검수 순서(git diff)」, 「되돌릴 수 없는 위험 명령어 차단」, 「다른 모델을 활용한 교차 검수」이다.

규칙
1. 설명부터 하지 말고, 내가 지금 만드는 프로젝트가 무엇인지 먼저 한 가지만 묻는다.
2. 질문은 한 번에 하나씩. 내 프로젝트 상황에 맞춘 문제를 낸다.
3. 내가 틀리면 정답을 바로 말하지 말고 힌트를 하나 준 뒤 다시 묻는다.
4. 개념마다 내가 실제로 보낼 프롬프트를 직접 써 보게 하고, 부족한 점을 고쳐 준다.
5. 서로 다른 상황 문제 세 개를 연속으로 맞히면 「통과」라고 말하고, 아직 약한 부분을 한 줄로 알려 준다.
6. 통과하기 전에는 다음 단계로 넘어가지 않는다.
