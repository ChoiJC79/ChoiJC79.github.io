09. 자동 배포와 정기 실행

git push를 통한 웹 배포 흐름을 이해하고 스케줄러를 활용해 정기 업무 스크립트를 무인 실행할 수 있다.

개념 읽기 → 실습 → 요점 카드 모두 「안다」 → 튜터와 대화로 다지기

왜 여기서 막히나

스크립트를 완성하고도 매일 아침 터미널을 열어 직접 명령어를 타이핑하여 실행하는 수동 업무에 머물러 있는 경우가 많습니다. 코드를 수정하고 나서 로컬 컴퓨터에서는 잘 동작하는데 왜 원격 GitHub Pages에는 반영되지 않는지 배포 흐름을 이해하지 못해 곤란을 겪습니다. 자동 실행 환경을 구성하지 않으면 담당자가 출장이나 휴가를 갔을 때 스크립트가 멈추고 맙니다. 코드의 저장소 반영과 정기적 자동 실행, 그리고 실패 시 로그를 확인하는 구조를 갖추어야 진정한 업무 자동화가 완성됩니다.

핵심 개념 세 가지

  1. git push와 배포 파이프라인로컬 컴퓨터에서 코드를 수정하고 commit을 하더라도 원격 GitHub 저장소에 push하지 않으면 배포되지 않습니다. git push 명령으로 코드가 원격 main 브랜치에 전달되면 GitHub 서버가 자동으로 변경 사항을 감지하여 웹 호스팅 공간으로 전송합니다. 내 컴퓨터의 파일 상태와 원격 호스팅 서버의 반영 상태를 일치시키는 연결 고리가 push입니다.
  2. OS 스케줄러사람이 컴퓨터 앞에 앉아 실행 명령을 내리지 않아도 정해진 시간마다 프로그램을 켜주는 운영체제 기능입니다. macOS에서는 launchd 서비스나 cron 명령을 사용하고 윈도우에서는 작업 스케줄러를 사용합니다. 컴퓨터가 켜져 있는 업무 시간에 매일 오전 8시 30분에 보고서 수집 스크립트가 자동으로 돌도록 등록할 수 있습니다.
  3. 실행 로그와 실패 확인자동으로 돌아가는 무인 스크립트는 화면에 오류가 나타나도 사람이 실시간으로 보지 못하므로 파일로 기록을 남겨야 합니다. 스크립트가 실행될 때 정상 시작 시간, 처리된 데이터 건수, 발생한 에러 메시지를 logs/app.log 같은 파일에 한 줄씩 덧붙여 기록합니다. 작업이 실패했을 때 기록된 로그 파일을 열어보고 어느 단계에서 멈추었는지 확인하여 문제를 진단합니다.

같은 일, 다른 요청

이렇게 요청하면

매일 자동으로 파이썬 스크립트 돌리고 싶은데 알아서 서버에서 돌려줘.

이렇게 요청한다

작성한 데이터 수집 스크립트(scripts/collect.py)를 정기 실행 환경으로 구성하고자 합니다.

[실행 환경]
- 운영체제: macOS
- 실행 주기: 평일 매일 오전 08:30 (월~금)

[요구사항]
1. macOS의 launchd 또는 crontab을 사용하여 백그라운드에서 실행할 수 있는 등록 스크립트와 실행 명령을 작성해 주십시오.
2. 파이썬 가상환경 경로와 프로젝트 절대 경로를 명시적으로 사용하여 환경 충돌이 없도록 설정해 주십시오.
3. 실행 시 표준 출력과 에러 출력을 logs/collect_YYYYMMDD.log 형태의 날짜별 로그 파일로 저장하도록 쉘 스크립트 래퍼를 구성해 주십시오.
4. 작업 성공 여부와 오류 발생 시 로그 파일의 위치를 확인할 수 있는 터미널 점검 명령어를 알려주십시오.

단순히 돌려달라는 요구 대신 사용자의 운영체제와 구체적인 스케줄 주기를 명확히 전달했습니다. 절대 경로와 가상환경, 로그 파일 저장 방식을 포함하여 사람이 없어도 문제 발생 시 원인을 추적할 수 있도록 완성도 높은 시스템을 요청했습니다.

30분 실습

  1. 홈페이지 코드의 제목 텍스트를 수정한 뒤 git commit과 git push origin main을 순서대로 실행합니다.
  2. GitHub 저장소의 Actions 탭이나 Pages 설정 화면에 들어가 배포 과정이 정상적으로 통과하는지 확인합니다.
  3. 간단한 날짜 출력 파이썬 스크립트를 작성하고 실행 결과를 파일로 덧붙여 쓰는 로그 출력 구문을 작성합니다.
  4. 터미널에서 crontab -e 또는 launchd plist 파일을 만들어 5분 뒤에 해당 스크립트가 1회 자동 실행되는지 확인합니다.

통과 기준

  • 로컬에서 수정한 웹페이지 변경 사항이 실제 인터넷 주소의 GitHub Pages 사이트에 3분 이내로 반영됩니다.
  • 지정한 시간이 지난 후 logs 폴더 안에 스크립트가 자동으로 생성한 실행 로그 파일이 존재합니다.
  • 로그 파일 첫 줄에 실행 시각과 최종 성공 완료 메시지가 정상적으로 기록되어 있습니다.

요점 카드

질문을 보고 답을 먼저 떠올린 뒤 눌러서 확인합니다. 답을 보지 않고 말할 수 있는 카드에만 「안다」를 표시하고, 모든 카드에 표시하면 이 단계를 통과합니다.

  1. 로컬 컴퓨터에서 커밋한 내용을 GitHub 원격 저장소에 반영하여 배포를 시작하는 명령어는?

    git push origin main입니다. 로컬 저장소의 변경 내역을 원격 main 브랜치로 전송해야 GitHub Pages 배포 파이프라인이 동작합니다.

  2. macOS 터미널에서 정기 실행 작업을 등록하고 수정하는 명령어는?

    crontab -e입니다. 설정 화면에 실행 주기와 실행할 스크립트 경로를 한 줄로 등록합니다. macOS에서는 잠자기 뒤에 놓친 작업도 실행해 주는 launchd(~/Library/LaunchAgents의 plist)를 더 권합니다.

  3. 스케줄러 무인 실행 시 터미널 화면 출력을 실시간으로 보지 못하는 문제를 해결하는 장치는?

    logs/app.log 같은 파일에 실행 시작 시각, 처리 건수, 오류 메시지를 덧붙여 기록하는 로그 파일입니다. 작업이 실패했을 때 기록된 로그를 열어 원인을 분석합니다.

  4. 스케줄러 자동 실행 시 수동 실행과 달리 모듈을 찾을 수 없다는 에러가 발생하는 원인은?

    스케줄러가 기본 시스템 환경에서 실행되므로 패키지가 설치된 가상환경 파이썬 절대 경로를 지정하지 않았기 때문입니다.

  5. 개인 업무용 컴퓨터가 꺼져 있어도 클라우드 서버에서 스크립트를 정기 실행해 주는 GitHub 기능은?

    GitHub Actions입니다. 저장소 내 워크플로 설정에 따라 GitHub 클라우드 서버의 가상 환경에서 무인 실행을 처리합니다.

  6. 정기 실행 스크립트가 1주일 동안 정상 작동했는지 검증하는 방법은?

    날짜별 로그 파일을 열어 성공 기록과 에러 발생 내역을 직접 확인합니다. 인공지능에게 구두로 묻거나 소스 파일 존재 여부만 확인해서는 실행 성공을 증명할 수 없습니다.

튜터와 다지기

문제를 맞혔어도 내 프로젝트에서 바로 쓰지 못하면 아직 아는 것이 아닙니다. 아래 프롬프트를 Claude에 붙여 넣으면 「통과」라고 할 때까지 내 상황에 맞춘 질문을 계속 받습니다.

너는 내 바이브 코딩 튜터다. 나는 「자동 배포와 정기 실행」 단계를 공부하고 있다.
이 단계의 목표는 「git push를 통한 웹 배포 흐름을 이해하고 스케줄러를 활용해 정기 업무 스크립트를 무인 실행할 수 있다.」
다룰 개념은 「git push와 배포 파이프라인」, 「OS 스케줄러」, 「실행 로그와 실패 확인」이다.

규칙
1. 설명부터 하지 말고, 내가 지금 만드는 프로젝트가 무엇인지 먼저 한 가지만 묻는다.
2. 질문은 한 번에 하나씩. 내 프로젝트 상황에 맞춘 문제를 낸다.
3. 내가 틀리면 정답을 바로 말하지 말고 힌트를 하나 준 뒤 다시 묻는다.
4. 개념마다 내가 실제로 보낼 프롬프트를 직접 써 보게 하고, 부족한 점을 고쳐 준다.
5. 서로 다른 상황 문제 세 개를 연속으로 맞히면 「통과」라고 말하고, 아직 약한 부분을 한 줄로 알려 준다.
6. 통과하기 전에는 다음 단계로 넘어가지 않는다.
