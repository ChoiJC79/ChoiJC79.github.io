11. 서브에이전트와 모델 나누기

작업 성격에 따라 서브에이전트와 모델을 분리하여 비용과 맥락을 효율적으로 관리할 수 있다.

개념 읽기 → 실습 → 확인 문제 5개 모두 맞히기 → 튜터와 대화로 다지기

왜 여기서 막히나

모든 작업을 메인 대화창에서 최상위 모델 하나로만 처리하면 대화 맥락이 금방 가득 차서 속도가 느려지고 토큰 비용이 급증합니다. 대규모 자료 조사나 파일 검색 작업을 메인 창에서 진행하면 정작 중요한 본문 작성 시점에 이전 지침을 잊어버리는 문제가 발생합니다. 단순 반복 변환이나 초안 작성 같은 가벼운 일까지 비싼 모델을 쓸 필요는 없습니다. 작업 성격에 맞추어 보조 에이전트와 적정 모델을 나누어야 안정적으로 긴 작업을 끌고 갈 수 있습니다.

핵심 개념 세 가지

  1. 서브에이전트(.claude/agents)독립된 작업 공간과 별도의 맥락 창을 가진 보조 작업자입니다. 방대한 공공 데이터 파일 탐색이나 웹 자료 조사처럼 중간 과정이 긴 작업을 맡긴 뒤 최종 요약 결과만 메인 대화로 전달받습니다. 메인 대화창의 맥락을 깨끗하게 유지하여 핵심 판단에 집중하게 돕습니다.
  2. 작업별 모델 분기(/model)단순 데이터 정제나 오탈자 교정 같은 기계적 작업은 경량 모델에 맡기고 복잡한 아키텍처 설계나 규정 검토는 상위 모델에 배정하는 전략입니다. Claude Code에서 /model 명령어를 사용하여 현재 작업 난이도에 맞는 모델로 전환합니다. 이렇게 모델을 나누면 작업 속도를 높이면서도 전체 API 비용을 크게 절감합니다.
  3. 병렬 작업의 파일 충돌 방지두 개 이상의 작업 단위나 에이전트가 동시에 실행될 때 동일한 소스 파일이나 문서를 동시에 수정하지 않도록 작업 범위를 격리하는 규칙입니다. 한쪽에는 표 데이터 가공을 맡기고 다른 쪽에는 스타일시트 작성을 맡기는 방식으로 대상 파일을 명확히 분리합니다. 파일 충돌로 인한 코드 유실이나 덮어쓰기 사고를 예방합니다.

같은 일, 다른 요청

이렇게 요청하면

시청 누리집에 있는 지난 3년 치 보도자료 파일 50개 다 읽고 분석해서 정리해 줘. 그리고 우리 홈페이지 스타일도 예쁘게 고쳐줘.

이렇게 요청한다

1. 자료 조사 서브에이전트를 호출하여 2023년부터 2025년까지의 보도자료 파일 목록을 조사하고 주요 정책 주제 5가지를 요약한 보고서 파일만 docs/summary.md로 생성합니다.
2. 메인 대화창에서는 요약된 docs/summary.md 파일만 참조하여 홈페이지 공지사항 본문을 작성합니다.
3. 홈페이지 스타일 수정 작업은 css/main.css 파일만 수정하도록 범위를 한정하며 요약 작업과 대상 파일이 겹치지 않게 분리합니다.

bad는 대량의 파일 검색과 스타일 수정이라는 서로 다른 성격의 작업을 한 대화창에 섞어 맥락 창을 낭비하고 혼란을 부릅니다. good은 대량 탐색 작업을 서브에이전트에 격리하여 요약 파일만 남기게 하고 수정 대상 파일을 명확히 한정합니다. 메인 대화창의 기억 용량을 보존하면서 파일 충돌 위험을 사전에 차단합니다.

30분 실습

  1. 1. 프로젝트의 .claude/agents 폴더에 research.md 파일을 생성하고 파일 조사 전용 보조 에이전트 지침을 작성합니다.
  2. 2. Claude Code 대화창에서 /model 명령어를 실행하여 현재 설정된 모델을 확인하고 가벼운 요약 작업을 위해 경량 모델로 전환해 봅니다.
  3. 3. 조사 에이전트에게 데이터 폴더 조사를 지시하여 결과 요약본을 단일 마크다운 파일로 출력하게 만듭니다.
  4. 4. 다시 상위 모델로 전환한 뒤 생성된 요약 파일을 바탕으로 홈페이지 메인 소개글을 작성하게 합니다.

통과 기준

  • 1. .claude/agents 폴더에 독립된 조사용 서브에이전트 설정 파일이 존재합니다.
  • 2. /model 명령어로 작업 난이도에 맞추어 모델을 자유롭게 변경할 수 있습니다.
  • 3. 메인 대화창에 대량의 검색 로그가 쌓이지 않고 최종 요약 파일만 깔끔하게 전달됩니다.

확인 문제

다섯 문제를 모두 맞혀야 이 단계를 통과합니다. 틀리면 해설을 읽고 다시 풀면 되고, 다시 풀 때마다 문제와 보기 순서가 바뀝니다.

튜터와 다지기

문제를 맞혔어도 내 프로젝트에서 바로 쓰지 못하면 아직 아는 것이 아닙니다. 아래 프롬프트를 Claude에 붙여 넣으면 「통과」라고 할 때까지 내 상황에 맞춘 질문을 계속 받습니다.

너는 내 바이브 코딩 튜터다. 나는 「서브에이전트와 모델 나누기」 단계를 공부하고 있다.
이 단계의 목표는 「작업 성격에 따라 서브에이전트와 모델을 분리하여 비용과 맥락을 효율적으로 관리할 수 있다.」
다룰 개념은 「서브에이전트(.claude/agents)」, 「작업별 모델 분기(/model)」, 「병렬 작업의 파일 충돌 방지」이다.

규칙
1. 설명부터 하지 말고, 내가 지금 만드는 프로젝트가 무엇인지 먼저 한 가지만 묻는다.
2. 질문은 한 번에 하나씩. 내 프로젝트 상황에 맞춘 문제를 낸다.
3. 내가 틀리면 정답을 바로 말하지 말고 힌트를 하나 준 뒤 다시 묻는다.
4. 개념마다 내가 실제로 보낼 프롬프트를 직접 써 보게 하고, 부족한 점을 고쳐 준다.
5. 서로 다른 상황 문제 세 개를 연속으로 맞히면 「통과」라고 말하고, 아직 약한 부분을 한 줄로 알려 준다.
6. 통과하기 전에는 다음 단계로 넘어가지 않는다.
