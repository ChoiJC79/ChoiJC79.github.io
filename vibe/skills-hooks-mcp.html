10. 스킬·훅·MCP로 반복 작업 고정하기

상황에 따라 규칙을 스킬, 훅, MCP 서버로 나누어 자동화할 수 있다.

개념 읽기 → 실습 → 요점 카드 모두 「안다」 → 튜터와 대화로 다지기

왜 여기서 막히나

Claude Code를 쓸 때 매번 같은 공문서 작성 규칙이나 배포 명령어를 대화창에 길게 설명하다 보면 피로가 쌓입니다. 대화가 길어지면 인공지능이 이전 지시를 잊어버려 같은 실수가 반복되기도 합니다. 자동화 지침을 한곳에만 적어 두면 정작 매번 검사해야 하는 보안 규칙이나 외부 데이터 조회가 누락됩니다. 세 도구의 역할 차이를 알아야 반복 지시 없이 일관된 결과를 얻을 수 있습니다.

핵심 개념 세 가지

  1. 스킬(.claude/skills)세 번 이상 반복해서 지시하는 복잡한 절차나 서식 작성법을 마크다운 문서로 만들어 등록하는 기능입니다. 필요한 시점에 Claude Code가 스스로 문서를 읽고 정해진 절차를 따라 작업합니다. 매번 긴 프롬프트를 복사해 넣지 않아도 정해진 표준 절차를 자동으로 수행합니다.
  2. 훅(Hooks)명령어나 도구가 실행되기 직전이나 직후에 자동으로 실행되는 강제 검사 장치입니다. settings.json에 등록하여 커밋 전 비속어 검사나 삭제 명령어 실행 전 차단 같은 안전장치를 만듭니다. 인공지능이 규칙을 건너뛰지 못하도록 기계적으로 통제할 때 사용합니다.
  3. MCP(Model Context Protocol)인공지능이 컴퓨터 외부 시스템이나 데이터베이스와 직접 정보를 주고받게 돕는 연결 규격입니다. 시청 누리집 공지사항 게시판 데이터나 내부 데이터베이스를 Claude Code가 직접 조회하게 만듭니다. 파일 수정이 아니라 외부 시스템의 데이터를 읽거나 쓸 때 도입합니다.

같은 일, 다른 요청

이렇게 요청하면

공문서 양식 맞춰서 홈페이지 공지사항 써줘. 지난번에 말한 대로 행정안전부 표기 규정 지켜야 해. 파일 올리기 전에 오탈자 검사도 꼭 해줘.

이렇게 요청한다

.claude/skills/announcement/SKILL.md에 정의된 공지사항 작성 스킬을 적용해서 새 글을 작성합니다.
1. 행정안전부 공문서 표기 규정에 맞추어 본문을 구성합니다.
2. settings.json의 PreToolUse 훅으로 등록된 금칙어 검사를 통과하는지 먼저 확인합니다.
3. 공지사항 작성이 끝나면 git diff 결과를 보여주고 변경 사항을 설명합니다.

bad는 매번 사용자가 기억에 의존해 규정과 검사 사항을 일일이 타이핑하여 요청합니다. good은 이미 등록된 스킬 경로와 훅 검사 체계를 지목하여 인공지능이 표준 절차를 스스로 확인하게 만듭니다. 이렇게 요청하면 대화가 길어져도 규칙이 누락되지 않고 일관된 문서가 나옵니다.

30분 실습

  1. 1. 프로젝트 폴더에 .claude/skills/format-check/SKILL.md 파일을 만들고 공문서 작성 표준 양식과 주의사항을 작성합니다.
  2. 2. Claude Code 대화창에서 Shift+Tab을 눌러 계획 모드로 전환한 뒤 작성한 스킬을 읽고 홈페이지 소개글을 수정하도록 요청합니다.
  3. 3. settings.json 파일의 훅 설정에 위험한 삭제 명령어 실행을 막는 PreToolUse 규칙을 추가합니다.
  4. 4. Claude Code 대화창에 /clear를 입력하여 대화를 비운 뒤 스킬 호출 명령을 내려 이전과 동일하게 서식이 유지되는지 확인합니다.

통과 기준

  • 1. .claude/skills/format-check/SKILL.md 파일이 존재하고 표준 양식 지침이 적혀 있습니다.
  • 2. 새 세션에서 스킬 이름을 언급했을 때 인공지능이 해당 문서를 읽고 규칙을 적용합니다.
  • 3. rm -rf 같은 위험 명령을 인공지능이 시도할 때 훅에 의해 차단되거나 경고가 나타납니다.

요점 카드

질문을 보고 답을 먼저 떠올린 뒤 눌러서 확인합니다. 답을 보지 않고 말할 수 있는 카드에만 「안다」를 표시하고, 모든 카드에 표시하면 이 단계를 통과합니다.

  1. 반복되는 서식 지침이나 표준 절차를 저장하는 마크다운 파일 경로는?

    .claude/skills/스킬명/SKILL.md입니다. 세 번 이상 반복해서 지시하는 복잡한 작업 규칙을 문서로 정리해 두면 Claude Code가 필요할 때 스스로 읽고 수행합니다.

  2. 위험한 명령어 실행이나 개인정보 유출을 도구 실행 전에 기계적으로 차단하는 설정 위치와 훅 이름은?

    settings.json 파일의 PreToolUse 훅입니다. 도구가 실행되기 직전에 검사 스크립트를 먼저 실행하여 조건에 맞지 않으면 작업을 강제로 중단합니다.

  3. Claude Code가 외부 데이터베이스나 누리집 API에 직접 접속하여 데이터를 조회하게 만드는 연결 규격은?

    MCP(Model Context Protocol)입니다. 단순 파일 편집을 넘어 외부 시스템과 통신하며 실시간 데이터를 읽거나 쓸 때 사용합니다.

  4. 스킬, 훅, MCP의 세 가지 기능 분담 기준은?

    문서 작성 서식이나 절차 지침은 스킬에 두고, 명령어 실행 차단 및 보안 검사는 훅에 등록하며, 외부 시스템 연동은 MCP 서버로 연결합니다.

  5. 자연어 당부나 CLAUDE.md 강조만으로 위험 파일 삭제를 막기 어려운 이유는?

    대화 지침은 모델이 복잡한 작업 중에 누락하거나 무시할 수 있기 때문입니다. 기계적인 실행 차단을 위해서는 PreToolUse 훅으로 도구 실행 자체를 가로채야 합니다.

  6. 대화 이력이 길어져 이전 지시가 흐려졌을 때 대화창을 비우는 명령어는?

    /clear입니다. 대화창을 초기화한 뒤 필요한 스킬을 다시 호출하여 일관된 작업 서식을 유지합니다.

튜터와 다지기

문제를 맞혔어도 내 프로젝트에서 바로 쓰지 못하면 아직 아는 것이 아닙니다. 아래 프롬프트를 Claude에 붙여 넣으면 「통과」라고 할 때까지 내 상황에 맞춘 질문을 계속 받습니다.

너는 내 바이브 코딩 튜터다. 나는 「스킬·훅·MCP로 반복 작업 고정하기」 단계를 공부하고 있다.
이 단계의 목표는 「상황에 따라 규칙을 스킬, 훅, MCP 서버로 나누어 자동화할 수 있다.」
다룰 개념은 「스킬(.claude/skills)」, 「훅(Hooks)」, 「MCP(Model Context Protocol)」이다.

규칙
1. 설명부터 하지 말고, 내가 지금 만드는 프로젝트가 무엇인지 먼저 한 가지만 묻는다.
2. 질문은 한 번에 하나씩. 내 프로젝트 상황에 맞춘 문제를 낸다.
3. 내가 틀리면 정답을 바로 말하지 말고 힌트를 하나 준 뒤 다시 묻는다.
4. 개념마다 내가 실제로 보낼 프롬프트를 직접 써 보게 하고, 부족한 점을 고쳐 준다.
5. 서로 다른 상황 문제 세 개를 연속으로 맞히면 「통과」라고 말하고, 아직 약한 부분을 한 줄로 알려 준다.
6. 통과하기 전에는 다음 단계로 넘어가지 않는다.
