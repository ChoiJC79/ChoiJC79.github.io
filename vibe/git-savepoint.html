04. git을 세이브포인트로 쓰는 법

작업 단위마다 커밋하고 AI가 바꾼 코드를 검토하며 망가졌을 때 이전 상태로 복구할 수 있다.

개념 읽기 → 실습 → 확인 문제 5개 모두 맞히기 → 튜터와 대화로 다지기

왜 여기서 막히나

AI에게 수정을 맡겼다가 기존 기능까지 망가진 경험이 누구나 있습니다. 어디서부터 잘못되었는지 모르면 코드를 전부 지우고 처음부터 다시 시작하게 됩니다. 저장 단위를 작게 나누고 변경 사항을 확인하는 습관이 없으면 복구할 기준점이 사라집니다. 안전망이 준비되어 있어야 AI에게 과감하게 수정을 요청할 수 있습니다.

핵심 개념 세 가지

  1. 작업 단위 커밋하나의 작은 기능이나 서식 수정이 정상 동작할 때마다 즉시 저장하는 방식입니다. 문제가 발생했을 때 정상 동작하던 직전 시점으로 바로 되돌아갈 수 있습니다. 여러 작업을 한꺼번에 몰아서 저장하면 문제 원인을 찾기 어렵습니다.
  2. git diff 검토AI가 코드를 수정한 직후 기존 파일과 달라진 줄을 직접 대조하는 과정입니다. 내가 요청하지 않은 엉뚱한 파일이나 기존 기능이 삭제되지 않았는지 확인합니다. 변경 내용을 승인하기 전에 터미널에서 diff를 읽는 습관이 필요합니다.
  3. 작업 취소와 되돌리기아직 커밋하지 않은 변경은 git restore로 즉시 버리고, 이미 커밋한 수정은 git revert로 안전하게 되돌립니다. AI가 코드를 꼬이게 만들었을 때 프롬프트로 설득하려 하지 않고 명령어로 깨끗하게 원상 복구합니다. 이전 세이브포인트로 즉시 돌아가는 기술입니다.

같은 일, 다른 요청

이렇게 요청하면

홈페이지 메뉴 구조 바꾸고 검색 기능도 추가해 줘. 그리고 CSS 디자인도 깔끔하게 다듬어 줘.

이렇게 요청한다

상단 메뉴 구조만 먼저 변경합니다. 다른 파일이나 CSS는 건드리지 마십시오.
작업을 시작하기 전에 현재 git 상태가 깨끗한지 확인하고 진행하십시오.
수정이 끝나면 브라우저에서 메뉴 링크가 작동하는지 확인하는 명령어를 안내해 주십시오.
검증이 끝나면 제가 커밋할 수 있도록 변경된 파일 목록만 요약하십시오.

한 번에 하나의 작업 단위만 지정하여 코드 범위가 넓어지는 위험을 차단했습니다. AI가 마음대로 다른 파일을 수정하지 못하도록 제한하고 검증 후 수동 커밋하는 절차를 명시했습니다. 결과적으로 문제가 생겨도 수정 범위를 쉽게 추적하고 되돌릴 수 있습니다.

30분 실습

  1. 현재 작업 중인 프로젝트 터미널에서 git status를 실행해 수정 중인 파일이 없는 깨끗한 상태인지 확인합니다.
  2. AI에게 웹페이지 제목 텍스트 하나만 바꾸는 작은 작업을 요청합니다.
  3. 수정이 끝난 뒤 터미널에서 git diff를 실행하여 바뀐 줄을 직접 확인합니다.
  4. git restore 명령어로 수정한 내용을 취소해 보고, 다시 요청하여 통과하면 git commit으로 세이브포인트를 만듭니다.

통과 기준

  • git status에서 변경된 파일이 내가 요청한 파일 하나뿐인지 확인했습니다.
  • git diff를 실행하여 추가된 줄과 삭제된 줄을 직접 눈으로 읽었습니다.
  • 원하지 않는 수정이 발생했을 때 명령어 한 줄로 이전 커밋 상태로 복구했습니다.

확인 문제

다섯 문제를 모두 맞혀야 이 단계를 통과합니다. 틀리면 해설을 읽고 다시 풀면 되고, 다시 풀 때마다 문제와 보기 순서가 바뀝니다.

튜터와 다지기

문제를 맞혔어도 내 프로젝트에서 바로 쓰지 못하면 아직 아는 것이 아닙니다. 아래 프롬프트를 Claude에 붙여 넣으면 「통과」라고 할 때까지 내 상황에 맞춘 질문을 계속 받습니다.

너는 내 바이브 코딩 튜터다. 나는 「git을 세이브포인트로 쓰는 법」 단계를 공부하고 있다.
이 단계의 목표는 「작업 단위마다 커밋하고 AI가 바꾼 코드를 검토하며 망가졌을 때 이전 상태로 복구할 수 있다.」
다룰 개념은 「작업 단위 커밋」, 「git diff 검토」, 「작업 취소와 되돌리기」이다.

규칙
1. 설명부터 하지 말고, 내가 지금 만드는 프로젝트가 무엇인지 먼저 한 가지만 묻는다.
2. 질문은 한 번에 하나씩. 내 프로젝트 상황에 맞춘 문제를 낸다.
3. 내가 틀리면 정답을 바로 말하지 말고 힌트를 하나 준 뒤 다시 묻는다.
4. 개념마다 내가 실제로 보낼 프롬프트를 직접 써 보게 하고, 부족한 점을 고쳐 준다.
5. 서로 다른 상황 문제 세 개를 연속으로 맞히면 「통과」라고 말하고, 아직 약한 부분을 한 줄로 알려 준다.
6. 통과하기 전에는 다음 단계로 넘어가지 않는다.
