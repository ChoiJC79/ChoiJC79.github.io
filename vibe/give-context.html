03. 정확한 맥락을 전달하는 방법

CLAUDE.md 규칙 작성, 대상 파일 지정, 예시 제공을 통해 필요한 맥락만 정확히 전달할 수 있다.

개념 읽기 → 실습 → 요점 카드 모두 「안다」 → 튜터와 대화로 다지기

왜 여기서 막히나

인공지능에게 아무런 배경지식을 주지 않으면 프로젝트 전체를 헤매며 엉뚱한 라이브러리를 설치하거나 기존 코딩 스타일을 무시합니다. 반대로 불필요한 대화가 50턴 이상 길어지면 앞서 약속한 지침을 잊어버리고 오작동하기 시작합니다. 프로젝트 공통 규칙은 파일에 기록하고, 작업 파일은 경로를 정확히 적어 주며, 길어진 대화는 주기적으로 비워야 일관성을 유지합니다.

핵심 개념 세 가지

  1. CLAUDE.md 지침 파일프로젝트 루트에 위치하며 Claude Code가 대화를 시작할 때마다 자동으로 읽는 지침서입니다. /init 명령으로 생성할 수 있으며, 공통 코딩 스타일, 금지 사항, 빌드 명령 등을 정의합니다. 매번 프롬프트에 같은 주의사항을 반복해서 적는 수고를 없앱니다.
  2. 정확한 파일 지정과 입출력 예시명령을 내릴 때 관련된 파일 경로를 직접 적고 변경 전후의 데이터 예시를 보여주는 방식입니다. 인공지능이 관련 없는 수십 개 파일을 읽느라 시간을 낭비하지 않도록 통제합니다. 구체적인 예시는 백 줄의 설명보다 정확하게 의도를 전달합니다.
  3. 대화 맥락 청소 (/clear와 /compact)대화가 오래 이어져 이전 기록이 쌓이면 인공지능이 과거 오류에 갇히거나 지시를 혼동합니다. 독립된 새 작업을 시작할 때는 /clear로 세션을 깨끗이 비우고, 진행 중인 맥락을 보존해야 할 때는 /compact로 요약합니다. 맥락 길이를 적절히 유지하는 것이 정확도를 높이는 지름길입니다.

같은 일, 다른 요청

이렇게 요청하면

저번에 만든 파일에서 날짜 나오는 부분 이상하니까 공무원 서식에 맞게 좀 고쳐줘.

이렇게 요청한다

scripts/format_report.py 파일의 날짜 출력 양식을 수정합니다.

[수정 대상 파일]
scripts/format_report.py

[요구 사항]
현재 '2026-03-05' 형태로 출력되는 날짜를 한국 공문서 표준 서식인 '2026. 3. 5.' 형태로 변경합니다.
- 연도 뒤, 월 뒤, 일 뒤에 각각 마침표를 찍고 공백 한 칸을 둡니다.
- 월과 일의 앞자리 0은 제거합니다.

[입출력 예시]
- 입력: datetime(2026, 3, 5)
- 출력: '2026. 3. 5.'
- 입력: datetime(2026, 11, 20)
- 출력: '2026. 11. 20.'

CLAUDE.md에 정의된 파이썬 표준 라이브러리 준수 규칙을 따르고, 다른 외부 패키지는 설치하지 마세요.

좋은 예시는 수정할 파일 경로를 명확히 지정하고 변경 전후의 입출력 예시를 구체적으로 제시했습니다. 또한 프로젝트 지침을 상기시켜 불필요한 라이브러리가 추가되는 현상을 막았습니다.

30분 실습

  1. 프로젝트 터미널에서 /init을 실행하거나 직접 CLAUDE.md 파일을 생성합니다.
  2. CLAUDE.md 안에 본인 업무의 필수 규칙(예: 외부 라이브러리 사용 금지, 공문서 날짜 형식 표기 등) 3가지를 작성합니다.
  3. 수정하려는 특정 파일 경로와 구체적인 입출력 예시 2쌍을 포함한 프롬프트를 전송합니다.
  4. 작업이 성공적으로 끝나면 /clear를 입력하여 세션을 초기화하고 다음 작업 준비를 마칩니다.

통과 기준

  • 프로젝트 루트에 유효한 규칙이 적힌 CLAUDE.md 파일이 존재합니다.
  • 프롬프트에 수정할 대상 파일의 상대 경로가 명시되어 있습니다.
  • 원하는 결과에 대한 입력과 출력 예시가 최소 1쌍 이상 프롬프트에 포함되었습니다.

요점 카드

질문을 보고 답을 먼저 떠올린 뒤 눌러서 확인합니다. 답을 보지 않고 말할 수 있는 카드에만 「안다」를 표시하고, 모든 카드에 표시하면 이 단계를 통과합니다.

  1. Claude Code에서 프로젝트 지침 파일의 뼈대를 자동으로 생성하는 명령어는 무엇입니까?

    /init 명령어를 실행합니다. 프로젝트 루트 디렉터리에 CLAUDE.md 지침 파일을 자동으로 생성합니다.

  2. 외부 라이브러리 설치 금지 같은 프로젝트 공통 규칙을 저장하는 파일명과 경로는 무엇입니까?

    프로젝트 루트에 위치하는 CLAUDE.md 파일입니다. Claude Code가 대화를 시작할 때마다 이 파일을 자동으로 읽어 규칙을 준수합니다.

  3. 독립된 새로운 작업을 시작할 때 이전 대화 기록을 완전히 비우는 명령어는 무엇입니까?

    /clear 명령어를 실행합니다. 불필요하게 누적된 대화 맥락을 초기화하여 인공지능이 과거 오류나 이전 지시에 갇히지 않게 만듭니다.

  4. 진행 중인 작업 맥락을 유지하면서 대화 길이를 줄여야 할 때 사용하는 명령어는 무엇입니까?

    /compact 명령어를 실행합니다. 지금까지의 핵심 대화 내용을 요약 압축하여 대화 맥락 용량을 확보합니다.

  5. 서식 변환 기능을 요청할 때 인공지능의 오차를 없애는 가장 확실한 전달 방식은 무엇입니까?

    변환 전 데이터와 변환 후 기대값을 짝지은 입출력 예시를 2쌍에서 3쌍 제시합니다. 구체적인 예시 데이터는 긴 줄글 설명보다 정확하게 요구사항을 전달합니다.

  6. 특정 파일의 버그 수정을 요청할 때 인공지능이 관련 없는 파일을 읽지 않도록 프롬프트에 적어야 하는 두 가지 정보는 무엇입니까?

    수정할 파일의 정확한 경로와 해당 파일의 현재 문제 증상입니다. scripts/format_report.py처럼 파일 경로를 명시해야 엉뚱한 파일을 수정하지 않습니다.

튜터와 다지기

문제를 맞혔어도 내 프로젝트에서 바로 쓰지 못하면 아직 아는 것이 아닙니다. 아래 프롬프트를 Claude에 붙여 넣으면 「통과」라고 할 때까지 내 상황에 맞춘 질문을 계속 받습니다.

너는 내 바이브 코딩 튜터다. 나는 「정확한 맥락을 전달하는 방법」 단계를 공부하고 있다.
이 단계의 목표는 「CLAUDE.md 규칙 작성, 대상 파일 지정, 예시 제공을 통해 필요한 맥락만 정확히 전달할 수 있다.」
다룰 개념은 「CLAUDE.md 지침 파일」, 「정확한 파일 지정과 입출력 예시」, 「대화 맥락 청소 (/clear와 /compact)」이다.

규칙
1. 설명부터 하지 말고, 내가 지금 만드는 프로젝트가 무엇인지 먼저 한 가지만 묻는다.
2. 질문은 한 번에 하나씩. 내 프로젝트 상황에 맞춘 문제를 낸다.
3. 내가 틀리면 정답을 바로 말하지 말고 힌트를 하나 준 뒤 다시 묻는다.
4. 개념마다 내가 실제로 보낼 프롬프트를 직접 써 보게 하고, 부족한 점을 고쳐 준다.
5. 서로 다른 상황 문제 세 개를 연속으로 맞히면 「통과」라고 말하고, 아직 약한 부분을 한 줄로 알려 준다.
6. 통과하기 전에는 다음 단계로 넘어가지 않는다.
