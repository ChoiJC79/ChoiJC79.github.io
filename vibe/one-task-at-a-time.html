02. 한 번에 하나의 작업만 지시하기

기능을 30분 단위 작업으로 나누고 체크리스트를 만들어 하나씩 차례대로 검증할 수 있다.

개념 읽기 → 실습 → 요점 카드 모두 「안다」 → 튜터와 대화로 다지기

왜 여기서 막히나

여러 요구를 한꺼번에 전달하면 인공지능은 5~6개 파일을 동시에 수정합니다. 그 과정에서 오류가 발생했을 때 어떤 변경 사항 때문에 문제가 생겼는지 원인을 찾기 어렵습니다. 결국 git 커밋을 되돌리거나 대화창을 비우고 처음부터 다시 시작하는 상황이 반복됩니다. 작업을 30분 단위의 독립된 작업으로 나누어 하나씩 해결해야 안전하게 완성할 수 있습니다.

핵심 개념 세 가지

  1. 30분 단위 분할하나의 프롬프트로 생성하고 사람이 직접 눈으로 동작을 확인할 수 있는 최소 단위의 일감입니다. 파일 1~2개 이내를 수정하고 즉시 화면이나 터미널에서 성공 여부를 검증할 수 있어야 합니다. 작업 단위가 작을수록 오류의 원인이 명확해집니다.
  2. 체크리스트 주도 작업전체 목표를 순서가 있는 목록으로 나열하고 현재 진행할 순번을 지정하는 방법입니다. Claude Code의 계획 모드(Shift+Tab)를 사용하거나 프롬프트 본문에 순서를 적어 진행합니다. 한 작업이 성공했을 때만 다음 순번으로 넘어갑니다.
  3. 작업 간 단위 커밋체크리스트의 항목 하나가 정상 작동하는 것을 확인한 직후 git commit을 남겨 안전장치를 만드는 방법입니다. 이후 단계에서 문제가 생겨도 직전 성공 지점으로 즉시 복구할 수 있습니다. 변경 이력이 깔끔하게 남아 협업과 유지보수에도 유리합니다.

같은 일, 다른 요청

이렇게 요청하면

홈페이지 메인 화면에 공지사항 게시판 추가하고, 엑셀 다운로드 기능 넣고, 다크 모드 버튼이랑 모바일 반응형도 한꺼번에 적용해 줘.

이렇게 요청한다

공지사항 페이지 개편을 4단계로 나누어 진행합니다.

[작업 순서]
1. index.html 상단에 최근 공지 5개를 보여주는 카드 목록 레이아웃 추가 (현재 작업)
2. 공지사항 클릭 시 상세 내용을 띄우는 모달 창 구현
3. 목록 하단에 notice.xlsx 파일로 내려받는 버튼 추가
4. 모바일 화면(폭 768px 이하) 대응 스타일 적용

지금은 1번 작업만 진행합니다. index.html과 style.css만 수정해 주시고, 2~4번 기능은 일절 건드리지 마세요. 작업이 끝나면 index.html을 브라우저로 열어 확인할 수 있는 상태를 만들어 주세요.

좋은 예시는 4단계 작업 계획을 제시한 뒤 철저하게 1번 작업만 수행하도록 통제했습니다. 수정 대상 파일의 범위를 제한하여 다른 코드가 망가지는 사고를 사전에 차단합니다.

30분 실습

  1. 최근 추가하고 싶었던 기능 하나를 고른 뒤 이를 구성하는 세부 단계를 3~4개로 쪼개어 적습니다.
  2. Claude Code에서 계획 모드(Shift+Tab)를 켜거나 프롬프트에 1번 항목만 진행하라는 명확한 명령을 작성합니다.
  3. 1번 작업 완료 후 브라우저나 콘솔에서 결과를 직접 확인합니다.
  4. 정상 작동을 확인하면 git commit을 실행하여 해당 단계의 완료 상태를 저장합니다.

통과 기준

  • 전체 작업이 3개 이상의 하위 체크리스트로 분할되었습니다.
  • 한 번의 요청에서 수정된 파일이 2개 이하로 제한되었습니다.
  • 해당 작업의 통과를 확인한 뒤 git 커밋 기록을 1개 이상 남겼습니다.

요점 카드

질문을 보고 답을 먼저 떠올린 뒤 눌러서 확인합니다. 답을 보지 않고 말할 수 있는 카드에만 「안다」를 표시하고, 모든 카드에 표시하면 이 단계를 통과합니다.

  1. 인공지능에게 한 번에 요청할 작업의 적절한 시간 단위와 파일 수정 범위는 어느 정도입니까?

    30분 단위이며 수정 파일은 1개에서 2개 이내입니다. 사람이 직접 화면이나 터미널에서 동작을 즉시 검증할 수 있는 크기로 쪼개어야 오류 원인을 명확하게 찾습니다.

  2. Claude Code에서 세부 작업 순서를 체계적으로 계획할 때 사용하는 단축키는 무엇입니까?

    Shift+Tab을 눌러 계획 모드로 전환합니다. 전체 목표를 순서가 있는 체크리스트로 나열하고 순서대로 실행하도록 통제합니다.

  3. 인공지능이 요청하지 않은 다음 단계 코드까지 임의로 수정했을 때 확인하고 복구하는 절차는 무엇입니까?

    git status와 git diff로 변경 사항을 확인하고 범위 밖의 수정을 취소합니다. 현재 진행 순번인 1번 작업의 결과물만 남겨서 검증합니다.

  4. 체크리스트의 한 단계를 완료하고 정상 동작을 확인한 직후 실행해야 하는 명령어는 무엇입니까?

    git commit을 실행하여 복구 지점을 만듭니다. 단계마다 저장 기록을 남겨두어야 다음 작업이 실패했을 때 직전 성공 상태로 즉시 되돌릴 수 있습니다.

  5. 여러 부가 기능을 추가할 때 체크리스트의 맨 첫 번째 작업으로 삼아야 하는 기준은 무엇입니까?

    기본 텍스트 입력과 목록 출력 기능을 먼저 만듭니다. 외부 서버 연동이나 부가 기능보다 가장 핵심이 되는 골격과 입출력 단계를 먼저 검증합니다.

  6. 인공지능에게 현재 순번의 작업에만 집중하도록 지시하는 프롬프트 문구 형식은 무엇입니까?

    「지금은 1번 작업만 진행합니다. index.html과 style.css만 수정해 주시고 2번 이후 기능은 일절 건드리지 마세요」와 같이 수정 대상 파일과 범위를 명시합니다.

튜터와 다지기

문제를 맞혔어도 내 프로젝트에서 바로 쓰지 못하면 아직 아는 것이 아닙니다. 아래 프롬프트를 Claude에 붙여 넣으면 「통과」라고 할 때까지 내 상황에 맞춘 질문을 계속 받습니다.

너는 내 바이브 코딩 튜터다. 나는 「한 번에 하나의 작업만 지시하기」 단계를 공부하고 있다.
이 단계의 목표는 「기능을 30분 단위 작업으로 나누고 체크리스트를 만들어 하나씩 차례대로 검증할 수 있다.」
다룰 개념은 「30분 단위 분할」, 「체크리스트 주도 작업」, 「작업 간 단위 커밋」이다.

규칙
1. 설명부터 하지 말고, 내가 지금 만드는 프로젝트가 무엇인지 먼저 한 가지만 묻는다.
2. 질문은 한 번에 하나씩. 내 프로젝트 상황에 맞춘 문제를 낸다.
3. 내가 틀리면 정답을 바로 말하지 말고 힌트를 하나 준 뒤 다시 묻는다.
4. 개념마다 내가 실제로 보낼 프롬프트를 직접 써 보게 하고, 부족한 점을 고쳐 준다.
5. 서로 다른 상황 문제 세 개를 연속으로 맞히면 「통과」라고 말하고, 아직 약한 부분을 한 줄로 알려 준다.
6. 통과하기 전에는 다음 단계로 넘어가지 않는다.
