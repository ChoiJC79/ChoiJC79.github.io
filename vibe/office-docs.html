18. pypdf와 HWPX로 문서 자동화하기

PDF 병합과 Word 서식 채우기를 실행하고 HWPX 문서의 내부 구조를 이해해 본문을 치환할 수 있다.

개념 읽기 → 실습 → 요점 카드 모두 「안다」 → 튜터와 대화로 다지기

왜 여기서 막히나

지방행정 실무에서는 한글 공문, 서식형 워드 보고서, 스캔본 PDF 취합이 일상의 대부분을 차지합니다. 구형 `HWP` 파일은 독자적인 압축 구조로 되어 있어 외부 파이썬 스크립트로 내용만 수정하기가 매우 어렵습니다. 최신 표준 형식인 `HWPX`는 사실상 XML 파일들을 묶어 놓은 zip 압축 파일이므로 압축을 풀어 본문 텍스트를 치환할 수 있습니다. `pypdf`로 첨부서류를 병합하고 `python-docx`로 워드 양식을 채우는 원리를 알면 AI에게 공문서 자동화 프로그램을 정확히 요구할 수 있습니다.

핵심 개념 세 가지

  1. pypdf의 텍스트 추출과 병합pypdf 라이브러리는 여러 개의 PDF 파일을 하나의 파일로 순서대로 합치는 PdfMerger 기능을 제공합니다. 각 페이지의 텍스트를 읽어오는 extract_text() 메서드를 통해 첨부서류의 본문 내용을 추출할 수도 있습니다. 스캔 이미지로 된 문서는 단순 텍스트 추출이 불가능하므로 문자 인식 도구가 별도로 필요하다는 점을 인지해야 합니다.
  2. python-docx를 통한 Word 서식 치환python-docx 라이브러리는 .docx 워드 문서의 문단과 표 내부 셀 텍스트를 프로그래밍 방식으로 제어합니다. 보고서 서식에 {{성명}}, {{금액}}과 같은 치환용 표식을 미리 넣어두고 파이썬으로 실제 값을 채워 넣는 작업이 가능합니다. 문단 스타일이나 표 테두리를 건드리지 않고 텍스트 단위인 Run 객체만 변경하여 기존 양식을 유지합니다.
  3. HWPX와 구형 HWP의 구조적 차이과거의 .hwp 파일은 독자적인 바이너리 형식이라 한글 프로그램 없이 파이썬으로 직접 조작하기가 매우 까다롭습니다. 반면 개방형 표준인 .hwpx는 본문이 section0.xml과 같은 XML 파일로 구성된 zip 압축 파일입니다. 파이썬의 zipfile 모듈로 내부의 section0.xml을 열어 텍스트를 치환한 뒤 다시 압축하면 서식을 유지한 채 내용을 갱신할 수 있습니다.

자주 쓰는 코드

from pypdf import PdfReader, PdfWriter  # PDF 읽기·쓰기 클래스를 불러옵니다
writer = PdfWriter()  # 합친 결과를 담을 빈 PDF를 만듭니다
writer.append('report.pdf')  # 보고서 본문 PDF를 뒤에 붙입니다
writer.append('attachment.pdf')  # 첨부 서류 PDF를 이어서 붙입니다
writer.write('final_submission.pdf')  # 합쳐진 최종 제출용 PDF를 저장합니다
reader = PdfReader('report.pdf')  # 텍스트를 뽑을 PDF를 엽니다
print(reader.pages[0].extract_text())  # 첫 쪽 글자를 화면에 출력합니다

같은 일, 다른 요청

이렇게 요청하면

한글 공문이랑 첨부 PDF 자동으로 합쳐서 출력물 만들어 줘.

이렇게 요청한다

`pypdf` 라이브러리를 사용하여 `본문.pdf`와 `첨부서류.pdf`를 순서대로 합치는 파이썬 스크립트를 작성해 주십시오.
결과 파일명은 `최종제출.pdf`로 저장하고 병합 완료 후 총 페이지 수가 몇 쪽인지 터미널에 숫자로 출력해 주십시오.
또한 `HWPX` 양식 파일인 `form.hwpx` 내부의 `Contents/section0.xml`에서 `{{부서명}}` 문자열을 `행정지원과`로 치환하여 새 파일로 저장하는 `zipfile` 기반 함수도 포함해 주십시오.

`good` 요청은 구형 HWP 대신 자동화가 가능한 PDF와 HWPX 형식을 명확히 구분하여 지시합니다. 사용할 라이브러리인 `pypdf`와 HWPX 내부의 실제 대상 XML 경로인 `Contents/section0.xml`을 지정하여 엉뚱한 코드가 생성되는 것을 방지합니다. 또한 결과 페이지 수 확인까지 요청하여 병합이 누락 없이 완료되었는지 즉시 점검할 수 있습니다.

30분 실습

  1. 실습용 PDF 파일 2개를 준비하여 작업 폴더에 doc1.pdf, doc2.pdf로 저장합니다.
  2. 터미널에서 pip install pypdf python-docx 명령을 실행하여 실습 라이브러리를 설치합니다.
  3. PdfMerger 코드를 실행하여 두 문서를 합친 merged.pdf를 만들고 맥 미리보기 앱으로 페이지 순서를 확인합니다.
  4. 한글 프로그램에서 새 문서를 열고 {{성명}}을 입력한 뒤 test.hwpx로 저장하고 터미널에서 unzip -l test.hwpx 명령으로 내부 구조를 확인합니다.

통과 기준

  • 생성된 merged.pdf를 열었을 때 doc1.pdf의 내용 뒤에 doc2.pdf의 페이지가 순서대로 연결되어 표시됩니다.
  • 파이썬으로 텍스트를 치환한 result.hwpx 파일을 한글 프로그램에서 열었을 때 파일 손상 경고창 없이 정상 실행됩니다.
  • 치환된 HWPX 문서의 표 서식과 글꼴 크기가 깨지지 않고 지정한 문자열만 변경되어 나타납니다.

요점 카드

질문을 보고 답을 먼저 떠올린 뒤 눌러서 확인합니다. 답을 보지 않고 말할 수 있는 카드에만 「안다」를 표시하고, 모든 카드에 표시하면 이 단계를 통과합니다.

  1. 여러 PDF를 하나로 합칠 때 쓰는 pypdf의 클래스와 메서드는?

    PdfWriter()를 만들고 append('파일.pdf')로 순서대로 붙인 뒤 write('결과.pdf')로 저장합니다. 예전 예제에 나오는 PdfMerger는 최신 pypdf에서 없어졌으므로 AI가 그 이름을 쓰면 PdfWriter로 바꿔 달라고 합니다.

  2. HWPX 문서의 본문 텍스트가 실제 XML 형태로 저장되어 있는 내부 압축 경로 파일명은?

    Contents/section0.xml입니다. HWPX 파일은 zip 압축 형식이므로 해당 XML 파일을 추출하여 텍스트를 치환할 수 있습니다.

  3. 구형 .hwp 파일을 외부 파이썬 라이브러리로 직접 텍스트 치환하기 어려운 기술적 이유는?

    .hwp는 OLE 복합 문서 안에 압축된 바이너리 레코드로 저장되는 한글 전용 형식이라, XML처럼 열어서 글자를 바꿀 수 없습니다. 자동화가 필요하면 한글에서 .hwpx로 저장해 쓰는 편이 현실적입니다.

  4. python-docx에서 기존 서식을 깨뜨리지 않고 특정 문단의 글자 내용만 안전하게 수정하는 최소 단위 객체는?

    Run 객체입니다. 문단 내부에서 동일한 서식을 공유하는 글자 묶음 단위인 run.text 값을 수정해야 서식이 유지됩니다.

  5. pypdf를 사용하여 PDF 파일의 첫 번째 페이지에서 글자를 읽어오는 메서드는?

    reader.pages[0].extract_text()입니다. PDF 각 페이지 객체에 접근하여 텍스트를 추출합니다.

  6. macOS 터미널에서 HWPX 파일의 내부 압축 파일 목록을 확인하는 쉘 명령어는?

    unzip -l 파일명.hwpx입니다. 확장자가 hwpx이더라도 실제로는 zip 파일이므로 내부 XML 파일 구조를 즉시 조회할 수 있습니다.
