01. 만들기 전에 스펙부터 작성하기

요청 전에 목적과 입출력을 정리한 스펙을 작성하고 인공지능에게 질문을 유도할 수 있다.

개념 읽기 → 실습 → 요점 카드 모두 「안다」 → 튜터와 대화로 다지기

왜 여기서 막히나

공무원 업무에서 기안문 없이 사업을 집행하지 않는 것과 같습니다. 목적과 완료 기준이 빠진 상태에서 바로 코드를 만들라고 요청하면 인공지능은 임의의 가정을 바탕으로 코드를 작성합니다. 결과물이 마음에 들지 않아 추가 수정을 지시할수록 코드가 엉키고 처음 의도와 멀어집니다. 짧은 명세서를 먼저 제시해 생각의 범위를 고정해야 원하는 결과를 얻습니다.

핵심 개념 세 가지

  1. 4요소 미니 스펙목적, 주 사용자, 입력과 출력 데이터, 완료 기준을 포함하는 10줄 안팎의 최소 기획서입니다. 구현 방법 대신 기능이 달성해야 하는 목표와 조건을 명확히 밝힙니다. 이 네 가지가 갖추어지면 인공지능이 엉뚱한 방향으로 코드를 작성하지 않습니다.
  2. 역질문 유도명세서를 제시한 뒤 곧바로 코드를 짜게 하지 않고 빠진 조건이나 모호한 부분을 먼저 묻도록 지시하는 방법입니다. 사용자가 미처 생각하지 못한 예외 상황을 설계 단계에서 발견합니다. 이 과정을 거치면 재작업 시간을 크게 줄입니다.
  3. 완료 기준의 구체화개발이 끝났음을 판단하는 관찰 가능한 조건을 명시하는 일입니다. 정상 작동 여부를 판단할 구체적인 화면 변화나 산출 파일 형식을 정의합니다. 모호한 완료 기준은 불필요한 재작업을 부릅니다.

같은 일, 다른 요청

이렇게 요청하면

우리 면사무소 민원 안내 페이지에 넣을 직원 담당 업무 검색창 하나 예쁘게 만들어줘.

이렇게 요청한다

면사무소 홈페이지에 들어갈 직원 업무 검색 기능을 만듭니다.

1. 목적: 민원인이 담당 부서와 직원을 빠르게 찾도록 돕습니다.
2. 사용자: 스마트폰 사용에 익숙하지 않은 고령 민원인.
3. 데이터: data/staff.json 파일의 이름, 직급, 담당업무, 전화번호 필드를 사용합니다.
4. 화면 및 동작: 상단 검색창에 단어를 치면 실시간으로 결과 표가 축소되며, 일치 단어는 강조 표시합니다.
5. 완료 기준: 검색어를 지우면 전체 목록 20명이 다시 나타나고, 검색 결과가 없을 때는 「담당 직원이 없습니다. 총무계(041-000-0000)로 문의하세요」 문구가 표시됩니다.

코드를 작성하기 전에 위 내용에서 모호하거나 구현을 위해 추가로 결정해야 할 사항이 있다면 3가지만 먼저 질문해 주세요.

좋은 예시는 주 사용자와 사용할 데이터 경로, 구체적인 예외 문구까지 명시했습니다. 또한 코드를 바로 생성하지 않고 질문을 먼저 던지게 하여 누락된 요구사항을 사전에 확인합니다.

30분 실습

  1. 현재 운영 중인 GitHub Pages나 작성했던 업무 스크립트에서 개선할 기능 하나를 선택합니다.
  2. 메모장에 목적, 주 사용자, 입력과 출력 데이터, 완료 기준을 각각 두 줄씩 적어 4요소 미니 스펙을 만듭니다.
  3. Claude Code에 해당 스펙을 제시하고 「코드를 작성하기 전에 불명확한 부분을 질문하라」고 프롬프트를 전송합니다.
  4. 인공지능이 제시한 질문 2~3개에 답변하여 최종 확정된 명세를 얻습니다.

통과 기준

  • 명세서에 목적, 사용자, 입출력, 완료 기준 4가지가 모두 기록되어 있습니다.
  • Claude Code가 코드를 바로 출력하지 않고 추가 질문을 최소 2개 이상 제시했습니다.
  • 인공지능의 질문에 답변하여 수정된 요구사항이 한 화면 안에 정리되었습니다.

요점 카드

질문을 보고 답을 먼저 떠올린 뒤 눌러서 확인합니다. 답을 보지 않고 말할 수 있는 카드에만 「안다」를 표시하고, 모든 카드에 표시하면 이 단계를 통과합니다.

  1. 4요소 미니 스펙에 반드시 포함해야 하는 네 가지 항목은 무엇입니까?

    목적, 주 사용자, 입력과 출력 데이터, 완료 기준입니다. 구현 방법 대신 기능이 달성해야 하는 목표와 조건을 10줄 안팎으로 정리합니다.

  2. 미니 스펙 문서의 권장 분량은 어느 정도입니까?

    10줄에서 20줄 안팎입니다. 너무 짧으면 인공지능이 자의적으로 판단하고 너무 길면 핵심 조건을 파악하기 어렵습니다.

  3. 인공지능이 임의로 코드를 작성하지 못하도록 막는 질문 유도 문구는 무엇입니까?

    「코드를 작성하기 전에 빠진 조건이나 확인이 필요한 사항을 먼저 질문해 주세요」라고 지시합니다. 사용자가 미처 생각하지 못한 예외 상황을 설계 단계에서 발견하게 만듭니다.

  4. 개발 완료 여부를 객관적으로 판단하기 위해 작성하는 완료 기준의 예시는 무엇입니까?

    「생성 버튼을 누르면 10초 이내에 out.csv 파일이 생성되고 5개 열의 헤더가 채워진다」와 같이 정의합니다. 시간, 파일명, 데이터 열 개수처럼 눈으로 관찰 가능한 구체적인 수치를 명시합니다.

  5. 인공지능의 역질문 중 아직 행정 절차가 확정되지 않은 항목이 있을 때 처리 기준은 무엇입니까?

    아직 미정인 기준은 기본값으로 임시 처리하도록 명시하고 확정된 기준만 답변합니다. 전체 작업을 중단하지 않고 개발 범위를 안정적으로 통제합니다.

  6. Claude Code에 프롬프트를 전송하기 전에 가장 먼저 수행해야 하는 작업은 무엇입니까?

    목적, 사용자, 입출력, 완료 기준을 정리한 4요소 미니 스펙을 작성하는 작업입니다. 스펙 없이 코드를 생성하면 계산 공식의 오류나 방향 착오를 수정하느라 시간을 낭비합니다.

튜터와 다지기

문제를 맞혔어도 내 프로젝트에서 바로 쓰지 못하면 아직 아는 것이 아닙니다. 아래 프롬프트를 Claude에 붙여 넣으면 「통과」라고 할 때까지 내 상황에 맞춘 질문을 계속 받습니다.

너는 내 바이브 코딩 튜터다. 나는 「만들기 전에 스펙부터 작성하기」 단계를 공부하고 있다.
이 단계의 목표는 「요청 전에 목적과 입출력을 정리한 스펙을 작성하고 인공지능에게 질문을 유도할 수 있다.」
다룰 개념은 「4요소 미니 스펙」, 「역질문 유도」, 「완료 기준의 구체화」이다.

규칙
1. 설명부터 하지 말고, 내가 지금 만드는 프로젝트가 무엇인지 먼저 한 가지만 묻는다.
2. 질문은 한 번에 하나씩. 내 프로젝트 상황에 맞춘 문제를 낸다.
3. 내가 틀리면 정답을 바로 말하지 말고 힌트를 하나 준 뒤 다시 묻는다.
4. 개념마다 내가 실제로 보낼 프롬프트를 직접 써 보게 하고, 부족한 점을 고쳐 준다.
5. 서로 다른 상황 문제 세 개를 연속으로 맞히면 「통과」라고 말하고, 아직 약한 부분을 한 줄로 알려 준다.
6. 통과하기 전에는 다음 단계로 넘어가지 않는다.
