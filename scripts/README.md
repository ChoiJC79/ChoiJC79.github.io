# 칼럼 1개 추가 절차

칼럼(`column.html`)은 세 곳의 파일이 서로 맞물려 돌아간다.

| 파일 | 역할 |
|------|------|
| `💬 칼럼·기고.md` | 원고 원본 |
| `column.html` | 목록 페이지 정본. `AUTO:TAGS`(태그 필터 버튼) / `AUTO:INDEX`(전체 목록 `<li>`) / `AUTO:CARDS`(카드 `<article>`) 세 블록과 "N편" 카운트 라벨을 담고 있다 |
| `columns/*.html` | 개별 칼럼 전문 페이지. `build_columns.py`가 생성한다 |

> `columns.json`이나 `col_data.js` 같은 파일은 이 프로젝트에 없다. 동기화는 위 세 파일 사이에서만 발생한다.

이름과 달리 `AUTO:*` 주석은 지금 어떤 스크립트도 자동으로 채우지 않는다. `column.html`은 완전히 수동 편집 파일이므로, 새 칼럼을 추가할 때 아래 절차를 빠짐없이 따라야 한다.

---

## 절차 (편집 순서 그대로)

### 1) 원고 작성 → 운영자 확인
채팅창에 초안을 먼저 출력해 승인을 받는다. `CLAUDE.md`의 글쓰기 기준(카테고리별 톤, "에스파냐" 표기 등)을 따른다. 이 단계에서는 아직 어떤 파일도 건드리지 않는다.

### 2) `💬 칼럼·기고.md` 끝에 추가
```markdown
## 칼럼 제목 | YYYY-MM-DD | 태그1·태그2

본문...

---
```
파일 맨 끝에 붙인다. `---` 구분자를 반드시 넣는다. 저장 후 null 바이트 오염 여부를 확인한다(`raw.replace(b'\x00', b'')`).

### 3) `column.html` 세 블록 + 카운트 라벨을 한 번에 수정
슬러그를 정한다 (`YYYYMMDD제목축약` 형태, 기존 파일명 패턴 참고). 아래 다섯 곳을 **전부** 고쳐야 한다.

1. **`AUTO:TAGS`** (161~163행 부근) — 신규 태그가 있으면 `<button class="tag-btn" onclick="filterCol(this,'태그명')">태그명</button>` 추가. 기존 태그를 재사용하면 이 블록은 안 건드려도 된다.
2. **`AUTO:INDEX`** (`<ol id="idx-list">` 안, 167~198행 부근) — 날짜 내림차순 위치에 `<li class="idx-row" ...>` 한 줄 삽입. 기존 항목 형식을 그대로 복사해서 슬러그·날짜·제목·태그만 바꾼다.
3. **`AUTO:CARDS`** (`<div class="col-list">` 안, 204~247행 부근) — 같은 위치에 `<article class="col-item" data-slug="...">` 카드 블록 삽입. 사진 경로(`/img/...`)도 함께 넣는다.
4. **카드 번호 밀기** — 새 칼럼이 목록 맨 위(최신 날짜)에 들어가면, 그 아래 기존 카드들의 `<span class="col-num">`과 `<span class="col-visual-num">` 값을 전부 +1 해야 한다. 중간에 끼워 넣는 경우 그 아래 카드들만 밀면 된다.
5. **"N편" 라벨** — `<span class="idx-count">28편</span>` 같은 숫자를 총 개수에 맞게 +1 한다.

이 5개 중 하나라도 빠지면 다음 단계(4번)에서 잡히지 않고 조용히 배포될 수 있다. 그래서 5번 스크립트로 기계적으로 검증한다.

### 4) 개별 페이지 생성
```
python build_columns.py --check   # 매칭 여부만 미리 확인
python build_columns.py           # columns/{슬러그}.html 실제 생성
```
`--check` 출력에서 새 칼럼 옆에 `❌ 본문 없음`이 뜨면 md 원본의 제목/날짜가 `column.html` idx-list와 안 맞는 것이다. 날짜가 정확히 일치해야 매칭되므로 가장 먼저 의심할 곳이다.

### 5) 동기화 검증
```
python scripts/check_columns_sync.py
```
아래 "검증 스크립트가 잡아내는 것" 참고. `❌`가 하나라도 뜨면 배포하지 않는다.

### 6) 배포
`🚀 사이트에 올리기.bat` 실행. `column.html`, `columns/*.html`, `img/` 사진이 함께 올라간다 (`publish.py`가 `columns/`와 `img/` 폴더를 통째로 스캔해서 올리므로, 파일을 해당 폴더에 두기만 하면 개별 등록은 필요 없다).

---

## 동기화가 깨졌는지 확인하는 법

`scripts/check_columns_sync.py`가 아래를 자동 비교한다.

**1. 개수 일치**
- `💬 칼럼·기고.md`의 칼럼 개수
- `column.html`의 `idx-list` 안 `<li>` 개수
- `column.html`의 `col-item` `<article>` 개수
- `column.html`의 "N편" 라벨 값
- `columns/*.html` 실제 파일 개수

다섯 값이 하나라도 다르면 어느 항목이 몇 개인지 표로 보여준다. 예를 들어 `col-item`만 27개고 나머지가 28개면 "카드 블록 삽입을 빼먹었다"는 뜻이다.

**2. 슬러그 집합 일치**
`idx-list`의 슬러그, `col-item`의 `data-slug`, `columns/` 폴더의 파일명(확장자 제외)이 정확히 같은 집합인지 비교한다. 어디에만 있고 어디에 없는지 구체적으로 출력한다 (예: `columns/ 폴더에만 있음(유령 페이지)`, `idx-list에만 있음(카드/파일 누락)`).

**3. 카드 번호 순서**
개수와 슬러그가 다 맞아도, 새 칼럼을 목록 위쪽에 끼워 넣고 이후 카드 번호(`col-num`, `col-visual-num`)를 안 밀면 숫자가 중복되거나 어긋난다. 이건 개수 비교로는 절대 안 잡히는 실패 유형이라 별도로 01부터 순서대로 매겨져 있는지 검사한다.

셋 중 하나라도 `❌`면 스크립트가 종료 코드 1을 반환하므로, 배포 스크립트 실행 전 확인 습관을 들이면 된다.

```
python scripts/check_columns_sync.py
```

---

## 자주 하는 실수

- `column.html`에 `<li>`와 `<article>`은 추가했는데 "N편" 라벨 숫자를 안 올림 → 개수 비교에서 라벨만 `❌`로 뜬다.
- md 원본의 날짜와 `column.html` idx-list의 날짜가 하루라도 다름 → `build_columns.py`가 매칭을 못 해 본문이 빈 페이지가 생성된다 (`--check`로 사전에 확인).
- 새 칼럼을 최신 날짜로 맨 위에 넣고 카드 번호를 안 밈 → 개수/슬러그는 정상인데 번호만 어긋난다 (위 3번 검증으로만 잡힘).
- `columns/`에 파일은 만들었는데 `column.html`에 카드/idx-row를 안 넣음 → "유령 페이지"로 슬러그 비교에서 잡힌다.
